# Совместимость исполняемых файлов

Версия 0.7.0 experimental содержит четыре профиля Windows x64. Выбор выполняется по SHA-256 EXE, затем до первой записи в код проверяются десять участков загруженного образа. Неизвестный хеш или несовпадение кода отключает изменения рынка с записью причины в game.log.txt. Для неизвестного EXE журнал также содержит его хеш.

Генерация вызывается через внутренние функции игры. Используются адреса кода, глобальной экономики и смещения полей объектов. Совпадение видимого номера версии или поведения генератора не подтверждает совпадение этих данных.

## Статический анализ

Эталонный образ 1.61.1.9 извлечён из ранее сохранённой базы Ghidra без её изменения; исходный EXE этой версии заново не получен. Новые EXE скопированы из установленной игры и проверены по хешам.

Для temporary и Oculus сравнение достижимых инструкций всех шести функций с нормализацией относительных адресов дало совпадение: очистка вектора — 42 инструкции, базовое заполнение — 137, таймеры — 53, генератор — 776, очистка компании — 89, планировщик — 123. Внутренние переходы сравнивались по целевым инструкциям; смещения полей сохранялись при сравнении. Относительные вызовы и RIP-адреса нормализовались: такое сравнение не доказывает равенство всех вызываемых функций и данных.

В 1.62 совпадают очистка вектора, базовое заполнение и планировщик. В таймерах появились проверки переполнения при увеличении массива. Генератор имеет другой стековый кадр, изменения контейнерных операций и упаковки данных; слоты стека бюджета сдвинулись с +70 на +78. Очистка компании обращается к изменённым внутренним полям и виртуальному методу; DLL вызывает штатную функцию данной версии, не воспроизводит эти обращения самостоятельно.

Проверены используемые DLL цепочка прицепа economy+18 → player+78 → первый элемент → owner+48, поле времени economy+19C, массивы компании +48/+50 и +A0, сроки заказа +48/+60, вектор базовых заказов +78, контекст компании +68 и поля определения +C0/+C4/+D8/+E0. Штатный проход 1.62 по компаниям использует economy+28/+30 и последовательность clear → fill (вызовы 4AA429 и 4AA434). Слоты карты не расширяются.

tools/compare_executables.py воспроизводит сравнение достижимого кода по снимкам; нужен Python и Capstone 5. tools/ExportCompatibility.java извлекает эталон из базы Ghidra. Снимки и отчёты находятся в diagnostics/executables и не входят в дистрибутив.

## Проверки и ограничения

MSVC Release собран. 11 офлайн-проверок прошли: выбор профиля, четыре образа, таймеры, сочетания, курсор, уведомления, DX11 и список компаний. Проверки образов используют тот же валидатор, что DLL, отвергают чужие профили, усечённый образ и изменение каждого из десяти проверяемых участков. Для новых EXE проверяется также SHA-256; эталон проверяется как восстановленный образ.

Игровое тестирование новой DLL ещё не выполнено. На копии профиля для каждой ветки требуется проверить загрузку, добавление грузов, обновление заказов, принятие заказа, сохранение/загрузку и автоматическую генерацию. В журнале ожидаются название выбранного профиля и `v0.7.0`.

Автоматическое разрешение неизвестных будущих EXE в 0.7.0 не добавлено. Поиск по сигнатурам может уменьшить зависимость от небольших обновлений, но сам по себе не подтверждает совместимость ABI и структуры объектов. Проверять только 1.61/1.62 недостаточно.

Oculus добавлен как профиль функций рынка. Рендерер остаётся DirectX 11; вывод меню внутри VR-шлема и VR-ввод не реализованы. Проверка DX11 на WARP не подтверждает работу внутри шлема.

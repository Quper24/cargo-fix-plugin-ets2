# Совместимость исполняемых файлов

## 0.8.2: ручной бюджет и различимые предложения

Совместимость и оба набора шаблонов 0.8.1 сохранены. Исправлен ручной режим добавления: специальный первый слот не ограничивает перебор единственной комбинацией; новые дубли удаляются, итог ограничен пятью новыми различимыми предложениями на компанию. Автоматический бюджет остаётся равным 1. До записи кода по-прежнему проверяется штатная инструкция бюджета; при выгрузке восстанавливаются все её исходные девять байтов.

MSVC Release и 22 CTest-проверки прошли, включая исполнение перехода бюджета с проверками регистров, флагов, стека и таблицы раскрутки Windows. Подробности причины, адреса и границы проверки: [ручные предложения 0.8.2](owned-offers-0.8.2.md). [Инструкция выпуска](README-public-0.8.2.md). Игровая проверка ещё требуется.

## 0.8.1: совместимость по коду без ограничения по версии

В `src/plugin.cpp` удалены чтение SHA-256 и выбор точного EXE. `ResolveGameProfile` получает загруженный PE и SDK ID игры; версия EXE и его хеш не являются входами этого алгоритма. Ресурс версии читается только для журнала, и ошибка чтения не мешает проверке кода. Плагин по-прежнему рассчитан на Windows x64 / DirectX 11.

Одинаковые проверки инструкций, переходов, областей памяти, глобальных ссылок и точек перехвата теперь выполняются для двух наборов шаблонов: структур 1.61 и 1.62. Требуется ровно один полностью совпавший набор. Для 1.61 используются подтверждённые смещения бюджета +265/+26C и слот стека +70, для 1.62 — +268/+26F и +78. Адреса функций и экономики находятся заново. Участок с не относящимся к экономике номером строки диагностического сообщения исключён из дополнительного шаблона источника ссылки; две независимые ссылки на одну экономику и вызов функции экономики проверяются.

Поэтому 1.61.2, новый хеш 1.61/1.62 и даже иной будущий номер версии принимаются при сохранении проверяемой совместимой структуры. Изменение самих проверяемых функций может потребовать нового шаблона. Вызовы внутренних функций рынка не являются стандартным контрактом SCS Telemetry SDK; этот SDK используется для загрузки плагина и событий, а не предоставляет изменения рынка. Это не обещание совместимости с любым будущим изменением игры.

MSVC Release собран. **21 CTest-проверка прошла**, включая динамический поиск в ETS2 temporary 1.61.1.1, Oculus 1.61.1.1009, восстановленном образе 1.61.1.9 и пяти образах 1.62 из таблицы ниже. Для четырёх прежних образов динамически найденные адреса дополнительно сравнены с независимыми сохранёнными таблицами. Таблицы хешей в `game_profile_data.inc` сохранены как исторические офлайн-фикстуры; рабочий путь инициализации DLL их не использует.

В тестах меняется сам `VS_FIXEDFILEINFO` ресурса сохранённых EXE на 1.61.2.0, 1.62.999.65535 и 1.63.0.0: распознавание сохраняется. Это синтетические варианты старого кода; настоящие EXE этих будущих выпусков не получены и не проверены. Также прошли прежние проверки переноса разделов, неоднозначности, изменений инструкций/полей/ссылок, усечённого образа и интерфейса. Экспорт Ghidra 1.61.1.9 содержит дополнение до 64 MiB; тест загружает только `SizeOfImage`, не меняя исходный файл и не ослабляя проверки DLL.

Оба набора шаблонов воспроизводятся `tools/generate_game_signatures.py`; `--check` сравнивает с `src/game_signatures_161.inc` и `src/game_signatures_162.inc`. Нужны сохранённые исходные образы и Capstone 5 только для генератора. Старый `tools/generate_162_signatures.py` оставлен как совместимая точка входа для набора 1.62.

**Игровое тестирование 0.8.1 ещё не выполнено.** Инструкция установки и границы проверки: [README 0.8.1](README-public-0.8.1.md).

## История 0.8.0: ATS и ETS2 семейства 1.62

Для 1.62 используется `src/game_resolver.cpp`, без списка разрешённых SHA-256 и без проверки цифр после 1.62. Игра определяется по SDK ID (`ats` / `eut2`), семейство — по числовому ресурсу версии EXE. Поддерживаются Windows x64 и существующий интерфейс DX11.

В загруженном PE проверяются разделы и таблица функций x64. По её записям ищутся уникальные совпадения семи графов достижимых инструкций: очистка вектора, заполнение компании, заполнение таймеров, генератор своего прицепа, очистка компании, планировщик и штатный обход обновления компаний. Проверяются все собранные инструкции, размеры, буквальные константы/смещения полей, условные переходы, обе ветки и отсутствие перекрывающихся инструкций. PC-relative адреса разрешаются заново; граф допускает перемещение кода.

Дополнительно проверяются три фрагмента экономики: источник глобальной ссылки, начало вызываемой функции с чтением economy+19C и независимый второй источник той же глобальной ссылки. Для всех шаблонов согласуются повторные ссылки на функции и данные; вызовы очистки/заполнения должны вести именно к найденным функциям. Глобальная экономика должна находиться в выровненной доступной для записи области данных; функции — в читаемой исполняемой области без флага записи. Неоднозначность, изменение кода/связей и неверный PE отключают профиль до первой записи в код.

После разрешения адресов проверяются точные инструкции в местах перехватов и формируются прежние десять буквальных защитных проверок. Полная проверка графа выполняется до установки перехватов; защитные проверки и проверки непосредственно в установщиках сохранены. EXE 1.62 не переключается на старый профиль по хешу при неудаче разрешения.

Это не проверка всех вызываемых вспомогательных функций и виртуальных методов. Шаблоны с NOP, переходами и повторными ссылками генерирует `tools/generate_162_signatures.py`; режим `--check` проверяет воспроизводимость `src/game_signatures_162.inc`. Нужен Python с Capstone 5 только для этих инструментов, не для DLL.

MSVC Release 0.8.0 собран; 18 CTest-проверок прошли. Пять EXE 1.62 проверены тем же разрешителем, который использует DLL. Дополнительно проверены изменение метаданных и номера patch/build, синтетический перенос всех разделов на +10000 RVA, отказ при изменении полей/инструкций/вызовов/переходов/глобальной ссылки, неоднозначном совпадении и усечении образа. Экспорты SCS и версия/название DLL проверены. Старые проверки четырёх образов ETS2 и остальные проверки таймеров/интерфейса также прошли.

Совместимые изменения адресов и постороннего кода не требуют обновления DLL. Изменение проверяемых инструкций или структуры объектов может потребовать новый выпуск. Проверки не доказывают совместимость всех будущих изменений вспомогательных функций/данных и не заменяют игровое тестирование. **Игровая проверка 0.8.0 ещё не выполнена.**

## История: точные профили 0.7.0

Версия 0.7.0 experimental содержит четыре профиля Windows x64. Выбор выполняется по SHA-256 EXE, затем до первой записи в код проверяются десять участков загруженного образа. Неизвестный хеш или несовпадение кода отключает изменения рынка с записью причины в game.log.txt. Для неизвестного EXE журнал также содержит его хеш.

Генерация вызывается через внутренние функции игры. Используются адреса кода, глобальной экономики и смещения полей объектов. Совпадение видимого номера версии или поведения генератора не подтверждает совпадение этих данных.

## Статический анализ

Эталонный образ 1.61.1.9 извлечён из ранее сохранённой базы Ghidra без её изменения; исходный EXE этой версии заново не получен. Новые EXE скопированы из установленной игры и проверены по хешам.

Для temporary и Oculus сравнение достижимых инструкций всех шести функций с нормализацией относительных адресов дало совпадение: очистка вектора — 42 инструкции, базовое заполнение — 137, таймеры — 53, генератор — 776, очистка компании — 89, планировщик — 123. Внутренние переходы сравнивались по целевым инструкциям; смещения полей сохранялись при сравнении. Относительные вызовы и RIP-адреса нормализовались: такое сравнение не доказывает равенство всех вызываемых функций и данных.

В 1.62 совпадают очистка вектора, базовое заполнение и планировщик. В таймерах появились проверки переполнения при увеличении массива. Генератор имеет другой стековый кадр, изменения контейнерных операций и упаковки данных; слоты стека бюджета сдвинулись с +70 на +78. Очистка компании обращается к изменённым внутренним полям и виртуальному методу; DLL вызывает штатную функцию данной версии, не воспроизводит эти обращения самостоятельно.

Проверены используемые DLL цепочка прицепа economy+18 → player+78 → первый элемент → owner+48, поле времени economy+19C, массивы компании +48/+50 и +A0, сроки заказа +48/+60, вектор базовых заказов +78, контекст компании +68 и поля определения +C0/+C4/+D8/+E0. Штатный проход 1.62 по компаниям использует economy+28/+30 и последовательность clear → fill (вызовы 4AA429 и 4AA434). Слоты карты не расширяются.

tools/compare_executables.py воспроизводит сравнение достижимого кода по снимкам; нужен Python и Capstone 5. tools/ExportCompatibility.java извлекает эталон из базы Ghidra. Снимки и отчёты находятся в diagnostics/executables и не входят в дистрибутив.

## Проверки и ограничения

MSVC Release собран. 11 офлайн-проверок прошли: выбор профиля, четыре образа, таймеры, сочетания, курсор, уведомления, DX11 и список компаний. Проверки образов используют тот же валидатор, что DLL, отвергают чужие профили, усечённый образ и изменение каждого из десяти проверяемых участков. Для новых EXE проверяется также SHA-256; эталон проверяется как восстановленный образ.

Игровое тестирование новой DLL ещё не выполнено. На копии профиля для каждой ветки требуется проверить загрузку, добавление грузов, обновление заказов, принятие заказа, сохранение/загрузку и автоматическую генерацию. В журнале ожидаются название выбранного профиля и `v0.7.0`.

Автоматическое разрешение неизвестных будущих EXE в 0.7.0 не добавлено. Поиск по сигнатурам может уменьшить зависимость от небольших обновлений, но сам по себе не подтверждает совместимость ABI и структуры объектов. Проверять только 1.61/1.62 недостаточно.

Oculus добавлен как профиль функций рынка. Рендерер остаётся DirectX 11; вывод меню внутри VR-шлема и VR-ввод не реализованы. Проверка DX11 на WARP не подтверждает работу внутри шлема.

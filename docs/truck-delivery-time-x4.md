# Время на доставку ×4 — грузовые заказы

Ветка `dev`, версия 1.2.0 dev. В форме «Создать заказ» добавлена отдельная галочка «Время на доставку ×4 (только грузовики)», по умолчанию выключена.

Действует на выбранное предложение, создаваемое вручную в грузоперевозках или для собственного прицепа. Массовая генерация, прочие предложения, Road Trip и Coaches этой настройкой не изменяются. При повторном создании уже существующего совпадающего предложения с включённой галочкой оно также помечается.

Срок доступности предложения на рынке остаётся 48 игровых часов. Множитель применяется к штатной продолжительности доставки, включая предусмотренные игрой переправы, отдых и погрузку: `новый_крайний_срок = текущее_игровое_время + 4 × (штатный_крайний_срок − текущее_игровое_время)`. Нижняя граница окна доставки сохраняется. Умножение самого абсолютного игрового времени недопустимо.

Оба нативных метода окна доставки грузового предложения разрешаются по полному коду, графу вызовов фабрик и проверенным виртуальным таблицам. Галочка недоступна при несовместимом коде. Перехват касается только двух грузовых типов; используются точные пометки созданных предложений, а не глобальные коэффициенты экономики. Каждый вызов сначала вычисляет штатное окно и увеличивает полученный результат один раз. Поэтому повторный просмотр предложения не превращает ×4 в ×16.

Для ещё не принятых предложений пометки хранятся в `CargoControl.delivery-time.txt` рядом с DLL. Запись связывает компанию отправления, вид рынка и слот с отпечатком груза, получателя, срока предложения, количества, срочности и расстояния. После загрузки сессии ссылки восстанавливаются только при совпадении отпечатка. Если при очистке старых предложений слот сдвинулся, ищется единственное точное совпадение в той же компании и на том же рынке. Замена предложения без галочки удаляет прежнюю пометку этого слота. Файл содержит ограниченное число записей и заменяется через временный файл; при ошибке записи есть сообщение в журнале.

При принятии игра записывает увеличенный крайний срок в собственное сериализуемое поле грузового рейса `time_upper_limit`. Уже принятые рейсы плагин не переписывает и при загрузке не умножает повторно. Результат сохранения/загрузки нужно подтвердить игровым тестом.

## Проверено

- Release и CTest: 35/35.
- На семи EXE ATS/ETS2 1.62 проверены методы расчёта, их связь с виртуальными таблицами и отказ при изменении инструкций.
- Настоящие нативные методы выполнены в изолированной памяти теста: учтены переправа, отсутствие/наличие отдыха, время погрузки; проверены сохранение нижней границы, ×4 и повторный расчёт без накопления множителя.
- Отдельно проверены переполнение времени, истёкший срок и изоляция ключей разных рынков.
- DX11-предпросмотр: отдельная галочка помещается в грузовую форму; вкладка Road Trip сохранена.

## Проверить в игре

1. Для одинакового маршрута сравнить создаваемые предложения без галочки и с ней: оставшаяся продолжительность должна увеличиться вчетверо; доступность предложения остаётся 48 часов.
2. Принять заказ с ×4, проверить крайний срок в игре; сохранить и загрузить профиль — повторного увеличения быть не должно.
3. Повторить для собственного прицепа.
4. Сохранить ещё не принятое предложение, перезапустить ATS и загрузить профиль: его пометка должна восстановиться из файла рядом с DLL.
5. Убедиться, что другие грузовые предложения и Road Trip не изменились.

Игровая проверка этой возможности ещё не выполнена.

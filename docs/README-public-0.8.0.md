# Cargo Control 0.8.0 — experimental

Один плагин для **American Truck Simulator и Euro Truck Simulator 2 семейства 1.62** на Windows x64 / DirectX 11. Название, DLL и новые настройки: Cargo Control, `CargoControl.dll`, `CargoControl.ini`.

## Установка

1. Закройте игру. Для первого теста сделайте копию профиля.
2. Удалите прежнюю `CargoControlETS2.dll` из `bin/win_x64/plugins`, если она там есть. Положите туда `CargoControl.dll`. В каждой игре должна быть только одна DLL Cargo Control.
3. Для ATS используйте папку `American Truck Simulator/bin/win_x64/plugins`, для ETS2 — `Euro Truck Simulator 2/bin/win_x64/plugins`. В обе игры устанавливается один и тот же файл DLL.
4. Запустите игру с DirectX 11. В `game.log.txt` найдите `[QS - Cargo Control]`, свою версию EXE, сообщение `1.62 instruction/flow and reference checks passed` и `Cargo Control v0.8.0 experimental`.

INI необязателен. Старый `CargoControlETS2.ini` можно оставить: если нового INI нет, плагин прочитает прежние сочетания. При сохранении через меню создаётся `CargoControl.ini`; старый файл не перезаписывается. Файл `.ini.example` — только пример.

## Использование

Меню: **Ctrl+Alt+F9**. Горячие клавиши действий по умолчанию отключены и назначаются в меню.

- Автоматический фикс ограничивает попытки генерации предложений для своего прицепа и сохраняет неистёкшие предложения; ручное нажатие для его работы не требуется.
- «Добавить грузы» добавляет до пяти предложений на компанию для выбранного собственного прицепа. Действуют три независимых слота по 48 игровых часов.
- «Обновить заказы» выполняет штатное обновление рынка грузоперевозок и заказов агентств. Можно запускать из загруженного гаража без своего грузовика. Повторный запуск доступен через пять реальных секунд после завершения предыдущего.

Остановите грузовик перед использованием меню. Действия выполняются только после проверки доступности и стабильности данных экономики.

Русский/английский язык выбирается по настройкам соответствующей игры, включая `-homedir`. Для Oculus поддерживаются функции рынка; вывод меню внутри VR-шлема и VR-ввод не реализованы.

## Мелкие обновления 1.62

Цифры после `1.62` и SHA-256 EXE **не блокируют запуск**. Плагин ищет функции в загруженной игре и проверяет инструкции, переходы, используемые поля и связи функций/глобальных данных. Перемещение функций и данных допускается. Совместимые мелкие обновления принимаются автоматически.

Если изменится проверяемый внутренний код, структура данных или обнаружится неоднозначное совпадение, изменения рынка отключатся до установки перехватов; причина будет в журнале. Безусловная совместимость с любым будущим обновлением не гарантируется.

Сохранена прежняя поддержка трёх точных EXE ETS2 1.61: обычного 1.61.1.9, temporary 1.61.1.1 и Oculus 1.61.1.1009, с прежними проверками хеша и кода. Новые сборки 1.61 автоматически не добавляются.

## Проверка выпуска

MSVC Release собран; 18 офлайн-проверок прошли. Проверены ATS public 1.62.1.1, ATS Oculus 1.62.1.1001, ETS2 public 1.62.1.0, прежняя ETS2 beta 1.62.0.10 и дополнительный EXE обновления ATS из staging Steam. Проверка staging-файла не подтверждает завершённость установки этой сборки.

Проверки включают искусственное перемещение разделов EXE, изменение номера после 1.62 и метаданных, отказ при изменении инструкций/полей/вызовов/переходов, ссылки на другую экономику, неоднозначных совпадениях и усечённом образе. Проверены таймеры, сочетания, курсор и рендерер DX11 на WARP.

**Игровое тестирование 0.8.0 ещё не выполнено.** На копии профиля в каждой игре проверьте загрузку плагина, меню, добавление грузов со своим прицепом, обновление обоих рынков, принятие заказа, сохранение/загрузку и обычную автоматическую генерацию. При проблеме сохраните `game.log.txt` и `game.crash.txt`, если он появился. Отсутствие сбоев не следует из успешных офлайн-проверок.

Сохранения с некорректно расширенными слотами от отозванной версии 0.4 не исправляются этим выпуском.

## Сборка

Visual Studio 2022 Build Tools с C++, Windows SDK, CMake 3.25+ и официальный [SCS Telemetry SDK 1.16](https://modding.scssoft.com/wiki/Documentation/Engine/SDK/Telemetry).

```bat
cmake -S . -B build-0.8.0 -A x64 -DSCS_SDK_ROOT="C:/path/to/scs_sdk_1_16" -DCARGO_CONTROL_BUILD_CHECKS=ON
cmake --build build-0.8.0 --config Release
ctest --test-dir build-0.8.0 -C Release --output-on-failure
```

DLL: `build-0.8.0/bin/Release/CargoControl.dll`. EXE игр не входят в исходный архив; без локальных снимков соответствующие проверки образов пропускаются. Capstone нужен только для офлайн-исследования и воспроизведения таблицы сигнатур, для DLL он не требуется.

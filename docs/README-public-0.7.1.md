# Cargo Control ETS2 0.7.1 — experimental

Одна DLL для Windows x64 / DirectX 11 и следующих точных сборок ETS2:

- обычная 1.61.1.9;
- temporary_1_61 — 1.61.1.1s;
- oculus — 1.61.1.1009s;
- public_beta — 1.62.0.10s.

Версия определяется по хешу EXE. Перед изменением кода проверяются десять участков памяти. Неизвестная или изменённая сборка отключает функции рынка и записывает причину в game.log.txt. Поддержка будущих обновлений автоматически не включается.

## Установка

1. Закройте игру и сделайте копию тестового профиля.
2. Замените CargoControlETS2.dll в `Euro Truck Simulator 2/bin/win_x64/plugins`. Оставьте только одну DLL Cargo Control; существующий INI можно сохранить.
3. Запустите игру в DirectX 11. В журнале найдите `[QS - Cargo Control]`, название своей версии и `v0.7.1`.

Меню: **Ctrl+Alt+F9**. Действия: добавление до пяти предложений на компанию для своего прицепа и штатное обновление рынка грузоперевозок/заказов агентств. Для добавления действуют три независимых слота по 48 игровых часов; обновление заказов доступно через пять реальных секунд после завершения предыдущего. Клавиши действий по умолчанию отключены и назначаются в меню. Автоматический фикс генерации своего прицепа действует без ручного запуска.

Остановите грузовик перед использованием меню. Для первого теста загрузите копию сохранения, добавьте грузы, обновите заказы, проверьте оба рынка, принятие заказа и сохранение/загрузку. При проблеме сохраните game.log.txt и game.crash.txt, если он появился.

Oculus поддержан на уровне функций рынка. Меню внутри VR-шлема и VR-ввод не реализованы; интерфейс использует существующий рендерер DirectX 11.

Сборка и 12 офлайн-проверок прошли, включая проверку четырёх образов игры. Игровая проверка 0.7.1 ещё требуется для каждой ветки. Сохранения с расширенными слотами от отозванной версии 0.4 не исправляются этим выпуском.

Подробности адресов, хеши и границы проверки: docs/version-compatibility.md в исходном проекте. Поведение интерфейса и исправления курсора из 0.6.1 сохранены.

## Сборка из исходников

Нужны Visual Studio 2022 Build Tools с C++, Windows SDK, CMake 3.25+ и SCS Telemetry SDK 1.16. Укажите путь к распакованному SDK:

```bat
cmake -S . -B build -A x64 -DSCS_SDK_ROOT="C:/path/to/scs_sdk_1_16" -DCARGO_CONTROL_BUILD_CHECKS=ON
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

DLL: build/bin/Release/CargoControlETS2.dll. Исходный архив не содержит EXE игры; без локальных снимков проверки четырёх образов пропускаются, остальные восемь доступны.

## Изменения 0.7.1

Обновление рынка грузоперевозок и заказов агентств можно запускать из гаража, не нажимая «В путь» и не имея своего грузовика. Действуют те же кнопки меню и назначенные сочетания. Запрос больше не хранится до будущего выхода в мир: он обрабатывается на ближайшем событии кадра SDK, в том числе в меню.

Перед выполнением проверяются доступность памяти экономики, список компаний и стабильность снимка на двух последовательных кадрах; кадр сброса таймеров после загрузки не считается готовым. При неготовности отображается сообщение с просьбой дождаться загрузки и повторить действие. Это проверки наблюдаемых данных, а не подтверждённый внутренний флаг окончания загрузки. Поведение на реальных профилях и разных сценариях загрузки требует игрового тестирования.

Для добавления грузов своего прицепа нужен выбранный собственный прицеп. Если его нет, плагин объясняет причину и предлагает обновление рынка/агентств. Лимит генерации при отказе не расходуется. Лимиты и правила замены/добавления предложений не менялись.

Основной зелёный изменён на согласованный #9DDD8C: немного более яркий и насыщенный. Используется в меню и уведомлениях. Встроенный логотип остаётся без изменений.

Для первого теста загрузите профиль без своего грузовика, откройте меню в гараже, нажмите «Обновить заказы», дождитесь результата и откройте заказы агентств. Отдельно проверьте уведомление при добавлении грузов без выбранного собственного прицепа.

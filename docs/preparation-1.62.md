# Подготовка Cargo Control для ATS и ETS2 1.62

Зафиксировано 05.11.2026. На этом этапе только прочитаны и сохранены EXE.
Код, название продукта, DLL и установленные игры не изменялись.

## Задача следующего этапа

- Название продукта: Cargo Control, без ETS2 в конце.
- Поддержка ATS и ETS2 семейства 1.62; цифры после 1.62 не являются ограничением требования пользователя.
- Для проверки нужны два варианта ATS 1.62 и один ETS2 1.62.
- Сначала собрать исходные EXE, затем выполнять анализ и изменения плагина.
- Совпадение номера 1.62 само по себе не доказывает совместимость внутренних адресов и структур. Способ поддержки семейства ещё предстоит реализовать и проверить.

У двух ATS одинаковая числовая версия, но разные хеши сборки в ресурсе:
`d0f1015fe858348b05bf6cdc94b35ce50f1d620c` и
`485f3729eaeb858faf759d0bdd447459b0afe034`.
Второй файл взят из staging Steam во время незавершённого обновления; установленной второй версией его считать нельзя. TargetBuildID описывает цель обновления из appmanifest, а не независимо подтверждённую принадлежность EXE этому build ID. Эти два варианта относятся к oculus.

После сообщения пользователя об обновлении ATS до 1.62.1.1 отдельно прочитан и сохранён установленный EXE public. Версия подтверждена ресурсом файла, ветка public и завершённая установка (StateFlags 4) — appmanifest Steam. Теперь основные три образа для дальнейшей проверки собраны: ATS oculus 1.62.1.1001, ATS public 1.62.1.1 и ETS2 public 1.62.1.0. Staging-файл оставлен как дополнительный снимок. Старые копии не перезаписывались.

Проверены совпадение SHA-256 каждой копии с источником и заголовки PE x64. Анализ функций, совместимость плагина и запуск в играх не выполнялись.

Ранее сохранённый ETS2 public_beta 1.62.0.10 находится в diagnostics/executables/public_beta-1.62.0.10/eurotrucks2.exe. Он оставлен без изменений и не подменяет новый образ ETS2 1.62.1.0.
